## 二、后端问题清单

### 🔴 P0 — 高优先级（影响稳定性或安全）

#### P0-1 API Key 加密密钥复用风险
- **位置**：`src/modules/common/crypto.service.ts:10`、`src/modules/models/models.service.ts:310,321`
- **问题**：AES 加密密钥直接使用 `JWT_SECRET`，且 fallback 为硬编码 `your-jwt-secret`。若 JWT_SECRET 泄露，所有用户 API Key 同时泄露；若未配置环境变量，则使用默认弱密钥。
- **建议**：
  1. 使用独立环境变量 `AES_KEY`（32 字节）。
  2. 启动时校验密钥长度，低于 32 字节直接抛错退出。
  3. 移除 fallback 默认值。

#### P0-2 JWT 密钥存在默认值
- **位置**：`src/modules/auth/jwt.strategy.ts:16`、`src/modules/websocket/websocket.gateway.ts:42`
- **问题**：`JWT_SECRET` 默认值为 `your-jwt-secret`，生产环境如未配置将存在严重安全风险。
- **建议**：强制从环境变量读取，无值时 `bootstrap` 直接抛异常退出。

#### P0-3 全局异常过滤器未暴露 `path`
- **位置**：`src/common/filters/global-exception.filter.ts`
- **问题**：返回体缺少请求路径，日志也只记录 message，排查问题时难以定位。
- **建议**：返回体增加 `path`，日志增加请求方法和 URL。

#### P0-4 WebSocket 认证使用 `jwtService.verify` 未处理过期/异常分支
- **位置**：`src/modules/websocket/websocket.gateway.ts:42`
- **问题**：`jwtService.verify` 抛异常会被 catch，但 `client.disconnect()` 没有返回错误原因；token 过期直接断开，前端无法区分。
- **建议**：断开前 `client.emit('auth_error', { message: ... })`。

#### P0-5 UserService 临时用户逻辑残留
- **位置**：`src/modules/common/user.service.ts:20`
- **问题**：Auth 模块已实现，但仍保留 `ensureUserExists` 创建临时用户的逻辑，可能导致 JWT 验证通过却查无此人时自动生成脏数据。
- **建议**：Auth 已实现后应移除 `ensureUserExists`，改为直接抛 `UnauthorizedException`。

#### P0-6 请求日志中间件读取 `req.user` 类型断言
- **位置**：`src/modules/logger/request-logger.middleware.ts:15`
- **问题**：`(req as any).user?.id` 依赖 JwtGuard 先执行，但中间件在 Guard 之前运行，user 永远为 `anonymous`。
- **建议**：如需要真实 userId，改为在 Guard 之后通过拦截器记录；或明确记录为 anonymous。

### 🟡 P1 — 中优先级（影响正确性/体验）

#### P1-1 AdapterFactory 默认回退策略可能误用未验证模型
- **位置**：`src/common/adapters/adapter.factory.ts:70-76`
- **问题**：当用户传入未注册的 `modelId` 时，直接按 capability 回退到默认 Adapter，可能用错误模型调用 API（例如用户想调 `kling-pro` 但拼写错误被回退到 `deepseek-v3`）。
- **建议**：未注册 modelId 时抛 `NotFoundException`，除非显式配置 `allowFallback`。

#### P1-2 可灵视频 Key 验证仅校验格式
- **位置**：`src/modules/models/adapters/kling-video.adapter.ts:16-24`
- **问题**：`validateKey` 只校验 `ak:sk` 格式，没有真实调用可灵接口，用户可能配置错误 Key 后直到生成视频才失败。
- **建议**：调用可灵一个轻量接口（如 account/balance）做真实验证。

#### P1-3 MiniMax TTS Key 验证仅校验长度
- **位置**：`src/modules/models/adapters/minimax-tts.adapter.ts:16-22`
- **问题**：只校验长度 `>10`，无法识别无效 Key。
- **建议**：调用 `/v1/query_vendor` 或最小 TTS 请求验证。

#### P1-4 模型偏好 DTO 与前端字段不一致
- **位置**：`src/modules/models/dto/update-model-preference.dto.ts:8`、`src/modules/models/models.service.ts:345-350`
- **问题**：前端 `modelsApi.setPreferences` 只传 `{ projectId, modelId }`，但 DTO 要求 `defaults: Record<string, { modelId, apiKeyId?, parameters? }>`。
- **影响**：前端调用 `/models/preferences` 会触发 `ValidationPipe` 400 错误。
- **建议**：统一前后端接口契约，或拆分两个接口（快速设置 vs 高级偏好）。

#### P1-5 GenerationsService 中任务 capability 类型断言
- **位置**：`src/modules/generations/generations.service.ts:44`
- **问题**：`dto.capability as any` 绕过类型检查，可能传入非法 capability。
- **建议**：使用 `GenerationJobData['capability']` 联合类型并在入参前校验。

#### P1-6 QueueModule 只有 Producer 没有 Consumer
- **位置**：`src/modules/queue/queue.module.ts`、`src/modules/queue/queue.service.ts`
- **问题**：`addGenerationJob` 会把任务塞进 BullMQ，但没有任何 Worker 监听 `generation` 队列；任务状态永远是 `queued`。
- **建议**：补齐 `ImageWorker`、`VideoWorker`、`TTSWorker`，更新 `GenerationTask` 状态并推送 WebSocket。

#### P1-7 ComposeService 仅返回计划，未真实合成
- **位置**：`src/modules/compose/compose.service.ts:47-55`
- **问题**：FFmpeg 合成是产品核心卖点，当前返回 mock 计划。
- **建议**：实现 FFmpeg 调用或接入 `ffmpeg-static` + `fluent-ffmpeg`，生成真实 MP4 后上传 MinIO。

#### P1-8 StorageService 上传返回相对路径
- **位置**：`src/modules/storage/storage.service.ts:34`
- **问题**：`uploadBuffer` 返回 `/storage/${bucket}/${key}`，前端无法直接访问（无对应代理路由）。
- **建议**：返回完整 presigned URL 或提供 `/storage/*` 代理下载接口。

#### P1-9 分镜生成后删除旧分镜无事务
- **位置**：`src/modules/storyboard/storyboard.service.ts:96-126`
- **问题**：`deleteMany` 和 `create` 分开执行，中间失败会导致旧分镜已删、新分镜未创建。
- **建议**：包裹在 `$transaction` 中，或先创建新版本分镜再软删除旧版本。

#### P1-10 StoryboardController `assistantChat` 使用裸 `throw new Error`
- **位置**：`src/modules/storyboard/storyboard.controller.ts:116`
- **问题**：普通 Error 会被 GlobalExceptionFilter 转换为 500，消息为英文/中文混合。
- **建议**：统一使用 `NotFoundException('项目不存在')`。

#### P1-11 ModelsService `resolveApiKey` 中 `preference.defaults` 类型处理脆弱
- **位置**：`src/modules/models/models.service.ts:344-346`
- **问题**：`as Record<string, any>` + 直接取值，字段名错误时不报错但行为不可预期。
- **建议**：为 `ModelPreference.defaults` 增加 Zod/class-validator 校验结构。

#### P1-12 角色变体 ID 生成使用 `Date.now() + random`
- **位置**：`src/modules/characters/characters.service.ts:160-161`
- **问题**：高并发下有重复风险；不是 UUID。
- **建议**：使用 `uuid` 或 Prisma 默认 cuid。

## 四、错误提示统一规范建议

当前错误提示存在以下不一致：

| 场景 | 当前表现 | 建议 |
|------|---------|------|
| 后端 401 | 前端 interceptor 移除 token 并跳转 | ✅ 保持一致 |
| 后端 400/403/404 | 部分抛中文、部分抛英文、部分带服务商原始响应 | 统一由 GlobalExceptionFilter 返回 `{ code, message }` |
| 前端网络错误 | `error.message` 直接显示 | 封装为 "网络连接失败，请检查网络后重试" |
| 前端表单校验 | 原生 `required` + 部分手动判断 | 统一使用 react-hook-form + zod |
| 操作成功 | 多数使用 toast.success | ✅ 保持一致 |
| 操作失败 | 部分 alert、部分 toast | 全部改为 toast |

### 推荐错误码体系

```ts
// 后端返回
{
  "statusCode": 400,
  "code": "MODEL_KEY_MISSING",   // 业务错误码
  "message": "未找到图像生成模型的可用 API Key",
  "path": "/projects/xxx/storyboard/shots/yyy/preview",
  "timestamp": "2026-08-01T..."
}
```
