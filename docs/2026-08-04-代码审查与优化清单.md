## 三、业务逻辑问题

### 🔴 P0 — 必须修复

#### BIZ-1 批量生成无并发控制，可能瞬间打满 API 配额

- **文件**：`generate/page.tsx:156-159`
- **问题**：`handleGenerateAll` 用 `forEach` 同时触发所有分镜的 `createTaskMutation.mutate()`，如果有 20 个分镜，瞬间发出 20 个 API 请求。无并发限制、无整体进度展示、无取消能力。
- **建议**：
  1. 改为串行执行或 `p-limit` 限制并发数（建议 3）。
  2. 添加整体进度条（已完成/总数）。
  3. 添加"取消"按钮。

#### BIZ-2 分辨率与宽高比映射逻辑错误

- **文件**：`doubao-video.adapter.ts:74`
- **问题**：`resolution === '720p' ? '9:16' : '16:9'` — 将 720p 强制映射为竖屏、1080p 强制映射为横屏。逻辑完全错误，分辨率和宽高比是两个独立维度。
- **建议**：宽高比应由用户在项目创建时选择的 `aspectRatio` 决定，resolution 只控制清晰度。

#### BIZ-3 WebSocket 登录后无法自动重连

- **文件**：`lib/websocket.ts:135-156`
- **问题**：`useSocketConnection` 的 `useEffect` 空依赖数组 `[]`，只在组件挂载时执行一次。用户登录后 token 写入 localStorage，但 WS 不会自动建立连接，需要刷新页面。
- **建议**：监听 `accessToken` 变化或通过全局 auth 状态触发重连。

#### BIZ-4 JWT Token 无过期时间

- **文件**：`auth.service.ts:81`
- **问题**：`this.jwtService.sign({ sub: userId, email })` 未设置 `expiresIn`，token 永不过期。
- **影响**：一旦 token 泄露（XSS、日志泄露等），攻击者可永久冒充用户。
- **建议**：设置 `expiresIn: '7d'`，并实现 refresh token 机制。

### 🟡 P1 — 需要细化

#### BIZ-5 视频轮询超时后丢失任务上下文

- **文件**：`doubao-video.adapter.ts:161-211`
- **问题**：`pollTask` 最多等待 60×5s=300s（5 分钟）。超时后直接抛错，taskId 丢失，用户无法在后台继续等待结果。豆包 Seedance 视频生成实际可能需要 5-10 分钟。
- **建议**：
  1. 超时后返回 `{ status: 'processing', taskId }` 而非抛错，让 BullMQ Worker 定期重试。
  2. 增大最大等待时间或改为指数退避。

#### BIZ-6 乐观更新导致任务列表闪烁

- **文件**：`generate/page.tsx:94-135`
- **问题**：乐观更新插入 `temp-${Date.now()}` 临时任务，但后端返回的真实任务 ID 不同。`onSettled` 中 `invalidateQueries` 触发全量刷新，导致列表先出现临时项、再消失、再出现真实项，视觉闪烁。
- **建议**：移除乐观更新，改为 mutation pending 状态下在对应分镜上显示 loading 指示器。

#### BIZ-7 分镜生成无流式反馈

- **文件**：`studio/page.tsx:91-101`
- **问题**：LLM 生成分镜可能耗时 30s+，期间只有按钮文字"生成中..."，无流式输出或进度条。
- **建议**：使用 SSE 或 WebSocket 实现流式输出，逐步展示生成的分镜。

#### BIZ-8 API Key 删除无二次确认

- **文件**：`settings/models/page.tsx:357`
- **问题**：`deleteKeyMutation.mutate(editingKeyId)` 直接执行删除，误删后无法恢复。
- **建议**：弹出确认对话框，提示"删除后需要重新配置"。

#### BIZ-9 版本恢复无冲突检测

- **文件**：`projectsApi.restoreVersion`
- **问题**：直接覆盖当前数据，如果用户有未保存的编辑会静默丢失。
- **建议**：恢复前提示"当前未保存的编辑将丢失，是否继续？"。

#### BIZ-10 本地草稿永不过期

- **文件**：`studio/page.tsx:63-72`
- **问题**：localStorage 草稿以 `studio_draft_${projectId}` 为 key 存储，项目删除后残留，且无过期清理机制。
- **建议**：项目删除时清理对应 localStorage，或添加过期时间（如 30 天）。

#### BIZ-11 "极速创作"按钮无功能

- **文件**：`projects/page.tsx:37`
- **问题**：按钮已渲染但无 `onClick` 或 `href`，点击无反应。
- **建议**：链接到 `/quick-create` 页面或暂时隐藏按钮。

#### BIZ-12 时间轴 Tab 实际展示 TTS 面板

- **文件**：`studio/page.tsx:306`
- **问题**：`{activeTab === "timeline" && <TtsPanel ... />}` — Tab 名为"时间轴"但实际渲染的是 TTSPanel。
- **建议**：要么重命名为"配音"，要么实现真正的时间轴编辑器。

## 四、代码安全问题

### 🔴 P0 — 高危

#### SEC-1 JWT 无过期时间（同 BIZ-4）

- **文件**：`auth.service.ts:81`
- **严重性**：🔴🔴🔴
- **影响**：Token 永不过期，一旦泄露攻击者可永久访问用户数据。
- **修复**：添加 `expiresIn: '7d'`，实现 refresh token 机制。

#### SEC-2 后端注册接口缺少密码强度校验

- **文件**：`auth.service.ts:19-52` + `dto/register.dto.ts`
- **问题**：前端有 `minLength={6}` 但后端 RegisterDto 未验证密码长度。攻击者可直接调 API 注册 1 位密码账号。
- **修复**：在 `RegisterDto` 中添加 `@MinLength(6) @IsString()` 装饰器。

#### SEC-3 验证码 SVG 注入风险（同 UI-2）

- **文件**：`login/page.tsx:156`
- **严重性**：🔴🔴
- **修复**：DOMPurify 过滤或改用 base64 img 方案。

#### SEC-4 项目删除/更新可能缺少权限校验

- **文件**：需确认 `projects.controller.ts` 中的 delete/update 路由
- **问题**：需确认后端是否校验 `project.userId === currentUser.id`，否则攻击者可通过遍历 ID 删除/修改他人项目。
- **建议**：在 Service 层统一添加 `this.ensureOwnership(project, userId)` 校验。

#### SEC-5 前端 Token 存储在 localStorage，XSS 可窃取

- **文件**：`lib/api.ts:9`
- **问题**：`localStorage.getItem('accessToken')` — localStorage 可被任何同源 JS 访问。如果存在 XSS 漏洞（如 SEC-3），token 可被窃取。
- **建议**：
  1. 短期：加强 CSP 策略，禁止内联脚本。
  2. 长期：改用 `httpOnly` + `Secure` Cookie 存储 token。

### 🟡 P1 — 中危

#### SEC-6 composeApi 使用硬编码 projectId=0

- **文件**：`lib/api.ts:650`
- **问题**：`/projects/0/compose/distribute/validate` — 使用 `0` 作为占位 projectId 绕过了资源归属校验。
- **建议**：改为使用实际 projectId，或后端对此类接口做独立鉴权。

#### SEC-7 全局禁用 @typescript-eslint/no-explicit-any

- **文件**：`lib/api.ts:1`
- **问题**：`/* eslint-disable @typescript-eslint/no-explicit-any */` 全局禁用，大量 API 返回 `any` 类型，丧失编译期类型保护。
- **建议**：逐步为所有 API 定义返回类型，移除全局禁用。

#### SEC-8 外部 URL 未校验直接用于渲染和下载

- **文件**：`generate/page.tsx:329-339`（video src）、`generate/page.tsx:401`（download link）
- **问题**：`<video src={task.result.url}>` 和 `<a href={url} download>` 直接使用后端返回的 URL。如果 URL 被篡改为恶意站点，可能触发钓鱼下载。
- **建议**：校验 URL 域名是否在白名单内。

#### SEC-9 WebSocket auth token 可能被日志记录

- **文件**：`lib/websocket.ts:22`
- **问题**：Socket.IO 的 `auth: { token }` 在 handshake 阶段传输，如果后端有请求日志中间件，token 可能被明文记录。
- **建议**：确认 `request-logger.middleware.ts` 是否过滤了 auth 字段。

### 🔵 P2 — 低危

| # | 问题 | 建议 |
|---|------|------|
| SEC-10 | `console.log` 输出任务进度等业务数据 | 生产环境移除或降级为 debug 级别 |
